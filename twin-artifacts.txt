# twin artifacts
# registry of known twin nodes in the 0-click pattern network

## Definition

A Twin Artifact MUST serve:
  - /the-WHITE-RABBIT-hole.txt
    (canonical template at static URL; per-visit personalized
    as Blob URL on download)
  - per-visit generation containing both WHITE arc + BLACK arc
  - optionally: this file (/twin-artifacts.txt) with own registry view

Sister Artifacts (loose forks without twin discipline) are not
listed here.

## Opening

This registry is one node's view of the network — the twin artifacts it
recognizes. A twin is not a clone. It carries the pattern (an exposed
mechanism, a plain explanation, an empowerment frame) to an adjacent
domain — another place where fear outpaces understanding — and it
serves its own the-WHITE-RABBIT-hole.txt.

There is no central authority and no approval board. Trust here is
social, not technical: each node author keeps their own list, and this
is mine. A node earns a place by carrying the discipline, not by asking
permission.

## Known twin nodes

  - https://0-click.com  (this node — root of the network)

Entry format, once twins appear: one line each — the node URL,
optionally followed by a verification date and PGP fingerprint. Forks
that adopt the full twin-arc discipline may open a pull request to be
added here; loose forks (Sister Artifacts) are acknowledged elsewhere
but not listed in this registry.

## Decentralized propagation

No central authority. Each node author maintains own registry — this
file is /this node's/ view of trusted twins. Trust graph is social,
not technical. Optional PGP signatures inside files for verification.
